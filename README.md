# ShelfSense

**AMD Developer Hackathon ACT III · Reinvent Commerce**

Offline catalogue + review assistant: enrich product listings from titles/descriptions/reviews, then answer shopper questions with evidence citations.

Zero-spend, Python stdlib only. Retrieval runs locally; the cited shopper answer is generated by an open LLM served on AMD GPUs via the free AMD TokenFactory API (set `AMD_API_KEY`; offline fallback otherwise).

## One-liner demo story

Merchant loads 25 sample SKUs + reviews → ShelfSense fills missing `skin_type` / `concerns` / ingredients → shopper asks *“which SKU for dry skin?”* → ranked recommendations with review citations.

## Requirements

- Python **3.9+** (stdlib only: `http.server`, `csv`, `json`, `re`, …)
- No pip packages required for the MVP
- Offline works with no network; AMD inference needs `AMD_API_KEY` + internet

## Exact run commands

From this directory (`amd-act-iii/`):

```bash
# 1) CLI end-to-end (offline)
python3 run_demo.py
python3 run_demo.py "which SKU for dry skin?"
python3 run_demo.py "best mineral SPF for all skin types"

# 2) Local web UI (stdlib server)
python3 app/server.py
# open http://127.0.0.1:8765/
# optional custom port:
python3 app/server.py 8766
```

CLI writes `demo_last_answer.json` with the last Q&A payload.

## How enrichment works

`app/enrich.py` scans title + description + review text with keyword rules and fills **only empty** catalogue fields (`skin_type`, `concerns`), while merging inferred ingredients. Fully deterministic — same input → same output. Sources are tagged `catalogue` vs `inferred` in the UI.

## How Q&A works (local stub)

`app/similarity.py` builds a sparse **TF-IDF / bag-of-words** index over products and reviews, scores the query with cosine similarity, and `app/qa.py` aggregates scores per SKU and returns:

- a short natural-language answer
- ranked recommendations
- citations (product blurbs + review snippets)

The API labels the retriever as `local-tfidf-stub`.

## What runs on AMD (and what doesn't)

| Step | Where it runs |
| --- | --- |
| Catalogue enrichment (keyword rules) | local CPU, deterministic |
| Retrieval (TF-IDF cosine over products + reviews) | local CPU |
| **Final shopper answer: an open LLM writes a grounded, cited answer from the retrieved evidence** | **AMD TokenFactory / AMD Radeon Cloud (AMD GPUs, ROCm), OpenAI-compatible API** |

`app/amd_llm.py` is a stdlib-only client for the AMD TokenFactory shared endpoint. Every `/api/ask` response includes an `llm` field
(`used: true/false`, model, reason) so you can see whether the AMD call actually happened. Without a key, or if the call fails, ShelfSense
falls back to the offline deterministic answer and says so — it never pretends.

### Enable AMD inference (free, no card)

1. Sign in to the AMD TokenFactory (linked from the lablab event page; `notebooks.amd.com/tokenfactory`, AMD AI Developer Program login) and copy your `rc-...` key from a Public Free Model API dialog.
2. Run:

```bash
export AMD_API_KEY=rc-...            # never commit this
export AMD_MODEL=DeepSeek-V4-Flash   # any model from GET $AMD_BASE_URL/models
# export AMD_BASE_URL=...            # default https://developer.amd.com.cn/radeon/api/v1 (use the base URL your console shows)
python3 run_demo.py "which SKU for dry skin?"
python3 app/server.py
```

See `.env.example`. Roadmap: dense embeddings on a dedicated ROCm vLLM endpoint to replace TF-IDF retrieval (not implemented).

## API (local server)

| Method | Path | Purpose |
| --- | --- | --- |
| GET | `/` | Web UI |
| GET | `/api/health` | product/review counts |
| GET | `/api/catalogue` | enriched catalogue JSON |
| GET | `/api/ask?q=...` | Q&A |
| POST | `/api/ask` | JSON body `{"question":"...","top_k":5}` |
